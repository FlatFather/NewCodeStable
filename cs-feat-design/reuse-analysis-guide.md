# cs-feat-design 复用分析指南

本文件承接 `SKILL.md` 启动检查第 3 条，定义 design 前强制执行的相关代码搜索与复用清单格式。

这是"复用优先"文化的核心步骤。目标：在设计前发现所有可复用/可扩展的现有代码。

**a. 关键词提取**：
- 从需求中提取 3-5 个核心关键词（名词/动词）
- 示例：需求"根据 shopno 查询店铺 ID" → 关键词：shop, shopno, query, db, id

**b. 代码搜索**（按优先级顺序执行）：
- 优先：`mcp__fast-context__fast_context_search` 语义搜索（自然语言："查询店铺信息"）
- 备选：`grep -r` 精确搜索关键词（函数名、类名、注释）
- 范围：整个代码库（不限于特定目录）

**c. 复用清单产出**（必须格式，写入临时变量供后续使用）：
```markdown
## 复用清单

搜索关键词：[列出关键词]

### 可直接复用
- 函数名 (文件路径:行号)
  功能：[一句话描述]
  复用方式：直接调用

### 可扩展后复用
- 函数名 (文件路径:行号)
  功能：[一句话描述]
  当前限制：[为什么不能直接用]
  扩展方式：[如何扩展，如：加参数 X / 修改返回值 / 提取公共逻辑]
  兼容性：[如何保证不破坏现有调用]

### 不可复用（需新增）
- 情况 1：搜索了关键词 [X/Y/Z]，未找到相关函数
- 情况 2：函数 [name] 存在但不可复用，原因：[职责不匹配 / 技术栈不同 / 等]
```

**d. 复用判断规则**：
- 同表/同 API 查询 → 优先合并查询逻辑
- 类似算法/逻辑 → 优先提取公共函数
- 职责相近的模块 → 优先在该模块扩展
- 重复的工具函数 → 优先复用已有实现

**最小产出要求**：
- 必须产出上述格式的复用清单（即使是"未找到相关代码"）
- 找到 ≥1 个相关函数时，必须判断是"可直接复用"/"可扩展"/"不可复用"
- 如果有"可扩展后复用"项，必须在 design 第 1.5 节优先考虑扩展方案

**输出示例**（你的对话案例）：
```
复用清单已生成：

搜索关键词：shop, shopno, query, db, id

### 可扩展后复用
- get_shop_name_from_db (utils/db.py:123)
  功能：根据 shopno 查询 basic_shop_info 表返回 shop_name
  当前限制：只返回 shop_name，不返回 shop_id
  扩展方式：修改 SQL 查询同时 SELECT shop_id，返回 (shop_id, shop_name) 元组
  兼容性：添加可选参数 include_id=False，默认保持原行为

→ 建议：优先扩展现有函数，避免重复查询同一张表
```
