## 执行总结

### 问题现状

**用户反馈**：
> 工作流在使用的时候产出的方案偏新增逻辑，而不是根据现有的业务逻辑去扩展优化

**典型案例**：
- 需求："根据 shopno 查询店铺 ID"
- AI 设计：新增 `get_shop_id_from_db()` 函数
- 用户质疑：现有 `get_shop_name_from_db()` 已经在查同一张表，为什么不合并？
- 问题：AI 没有主动发现可复用的现有函数

### 优化目标

建立"**复用优先、扩展为主、新增为辅**"的工作流文化，通过系统性改造解决 AI 倾向新增的问题。

## 用户痛点解决

**你的案例**：根据 shopno 查询店铺 ID

### 优化前：
```
1. AI 设计：新增 get_shop_id_from_db()
2. 你发现：已有 get_shop_name_from_db() 在查同表
3. 你指出：为什么不合并查询？
4. AI 修改：确实可以合并

问题：你承担了本该 AI 做的工作
```

### 优化后：
```
1. 启动检查：搜索 "shop, shopno, query, db, id"
2. 复用清单：
   - get_shop_name_from_db (utils/db.py:123)
     可扩展后复用
     扩展方式：修改返回值为 (shop_id, shop_name)
3. design 第 1.5 节：
   策略：扩展为主
   扩展点：get_shop_name_from_db 增加可选参数 include_id=False
4. 你只需 review，不需要手动找复用点 ✓

结果：AI 主动发现复用机会
```
