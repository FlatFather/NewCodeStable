**更新退出条件**：增加第 2.5 节检查

## 核心机制

### 复用优先的三大支柱

```
┌─────────────────────────────────────────────────────────────┐
│  支柱 1：design 前强制复用分析                              │
│  ├─ 关键词提取 → 代码搜索 → 复用清单                        │
│  └─ 最小产出：必须产出复用清单（即使是"无相关代码"）        │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  支柱 2：design 第 1.5 节"复用与扩展策略"                   │
│  ├─ 复用清单 + 策略选择 + 策略说明                          │
│  └─ 新增理由必须格式（如果选择新增为主）                    │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  支柱 3：accept 第 2.5 节"复用策略审查"                     │
│  ├─ 策略执行验证 + 复用清单核对                             │
│  └─ 过度新增检查（主动发现遗漏）                            │
└─────────────────────────────────────────────────────────────┘
```

### 工作流增强

**优化前**：
```
brainstorm → design → plan → implement → accept
             ↑
        只读 architecture
        没有复用分析
```

**优化后**：
```
[扩展 vs 新增分诊] → design（强制复用分析 + 第 1.5 节策略）
                      ↓
                    plan（扩展场景专用模板）
                      ↓
                  implement
                      ↓
                  accept（第 2.5 节复用审查）
```
